设计端 JS 对接文档（UMD 单文件） ​

适用于 jQuery / 静态页面 / 无框架项目：引一个 JS 文件，new SeatMapDesigner(el, opts) 即用。Vue / webpack 项目请走 Vue 对接文档。

获取产物 ​

设计器以打包好的组件交付（不提供源码）。需联系开发者获取组件（交付包 seatmap-designer-pkg.tar.gz，内含单文件 seatmap-designer.umd.js）。

默认使用方式（解压交付包到项目后引入）：

bash
# 1. 把交付包解压到项目根目录
tar -xzf seatmap-designer-pkg.tar.gz
# 得到 seatmap-designer-pkg/seatmap-designer.umd.js

把 seatmap-designer.umd.js 拷到你的静态目录（或 public/），页面 <script> 引入即可：

html
<script src="/libs/seatmap-designer.umd.js"></script>

产物说明（JS 对接）：本文档对接的是 UMD 单文件 seatmap-designer.umd.js（vue / leafer / css 全内置 + CSS 内联，开箱即用）。 Vue 对接用的是另一个产物 seatmap-designer.es.js（ES 组件，vue 走外部依赖），见 Vue 对接文档。

产物只需任意静态服务器（nginx / IIS / python -m http.server）即可，无需 Node 环境、无需安装任何依赖（vue / leafer / css 已全内置）。

快速开始 ​

html
<div id="map" style="width:100%; height:100vh"></div>

<script src="/libs/seatmap-designer.umd.js"></script>
<script>
  const designer = new SeatMapDesigner(document.getElementById('map'), {
    // 保存唯一通道：宿主导函数。成功返回后端 { version }；失败弹提示后原样抛出
    saveHandler: async (payload) => {
      const res = await fetch('/venue/save', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(payload),   // payload 结构见后端接口文档「保存」（含乐观锁 version）
      })
      const body = await res.json()
      if (!res.ok || body.code !== 0) {   // 含乐观锁冲突 code:409
        alert(body.msg || '保存失败')     // 一切失败提示由宿主自管（组件不弹窗）
        throw new Error(body.msg || '保存失败') // 抛出 = 失败：组件保留快照与脏标记
      }
      return body.data                    // { version }：后端确认的新版本号，组件据此更新乐观锁
    },
  })

  // 加载：宿主自己请求接口，拿到后端原始格式数据后喂入
  const { venue } = await fetch('/venue?venue_id=' + id).then((r) => r.json()).then((b) => b.data)
  const { seatlist } = await fetch('/venue/seats?venue_id=' + id).then((r) => r.json()).then((b) => b.data)
  designer.setData(venue, seatlist)
</script>

大场馆分段加载 ​

两请求无依赖，可并行发出；轮廓先上屏、座位随后并入：

js
designer.setData(venue)            // ① 场馆主体（分区轮廓立即渲染）
designer.mergeSeats(seatlist)      // ② 座位到了再并入（不动视图）
// 可选：驱动内置加载 UI
// designer.setLoadPhase('venue') → 'seats' → ''

保存协议（务必注意） ​

  • 成功只有一种：return { version }（后端确认的新版本号，组件据此更新乐观锁基准）。旧契约 return true 仍兼容（版本按后端语义本地推断：建档=0、其后 +1），但建议返回真实 version。
  • 失败只有一种：抛出异常（throw）。false / undefined / 无 version 的对象一律按失败处理。失败 → 脏标记与快照保留（下次保存自动累计重发）。
  • 一切提示 UI 由宿主自管：成功提示、失败 alert、409 冲突提示都在 saveHandler 里做，组件对保存结果不弹任何窗、不上抛事件。未配置 saveHandler 时保存直接报错。
  • 乐观锁：payload.venue.version 为比对基准（后端不一致返 code: 409，HTTP 仍为 200）。收到 409 不要重试——唯一出口是提示用户后重新拉取场馆最新数据（setData 重载后 version 基准与 diff 快照一并刷新）。
  • 孤儿座位自动清理：setData / mergeSeats 载入时若发现排已不存在的残留座位，组件状态栏提示数量，并随下次保存的 seat_delete 捎带删除（saveHandler 无需特殊处理，透传即可）。

图片上传 ​

底图 / 水印 Logo 共用一个上传器，uploadHandler: (File) => Promise<图片完整URL>：

js
const designer = new SeatMapDesigner(el, {
  uploadHandler: async (file) => {
    const fd = new FormData()
    fd.append('file', file)
    const res = await fetch('/upload', { method: 'POST', body: fd })
    const body = await res.json()
    return body.data.url                 // 必须返回 http(s):// 完整 URL
  },
})

不配置则上传报错（无 dataURL 兜底）。

构造参数 ​

js
new SeatMapDesigner(el, {
  saveHandler,          // 保存通道 fn(payload)=>Promise<{version}>（成功返回后端新版本号；失败抛异常。与 setSaveHandler 等价，推荐构造时配齐）
  uploadHandler,        // 图片上传 fn(File)=>Promise<URL>
  defaultCategories,    // newVenue 默认类别 [{ name, color }]；null = 内置「普通区/VIP区」
  seatDefaults,         // { size, seatPitch, rowPitch } 座位尺寸/座距/排距默认
  limits,               // { rowSeats, dropTotal, sectionSeats, venueSeats } 数量上限
  zoom,                 // { step, min, max, wheelZoom, stickSpeed } 缩放；wheelZoom=false 滚轮只平移
  ui,                   // { topBar, toolBar, sidePanel, statusBar, zoomPad, layersPanel } 六区显隐
  tools,                // 工具白名单 key 数组；null = 全部
  theme,                // 'light' | 'dark' 初始主题
  debug,                // true 时输出开发性能日志；默认 false
})

除 saveHandler / uploadHandler / theme 外，后六组为「实例化自定义参数」，运行时可 setOptions(partial) 深合并修改；未知 key 会被忽略并告警。

实例方法 ​

方法说明
setData(venue, seatlist?)喂数据（后端原始格式；seatlist 可省，只上轮廓），主路径
mergeSeats(seatlist)分段喂座位：setData(venue) 后座位到达再并入（不动视图）
save()触发保存：走宿主导函数（saveHandler）
setSaveHandler(fn)注入宿主导函数（与构造参数等价）
setImageUploader(fn)注入图片上传器
getSavePayload()取当前全量保存 payload { save_type: 'full', venue, seatlist }，宿主手动回写用
exportJSON() / importJSON(json)设计器内部格式导入导出（迁移备份）
fit()视图适配全图
newVenue(init)新建空白场馆（带默认类别）；init：string=名字 或 { id, name, ...extra }（id 宿主预分配、extra 随保存透传回写）
setLoadPhase(p)驱动内置加载 UI：'venue' 全画布遮罩 / 'seats' 轻提示 / '' 结束
getState(){ venueId, name, sections, seats, saving, dirty, version }
setOptions(partial)运行时深合并自定义参数
setTheme(t)运行时切换主题
exportPDF(opts) / exportSVG(opts) / exportPNG(opts)导出场馆大图为 PDF / SVG / 超高清 PNG，触发浏览器下载
on(evt, fn) / off(evt, fn)事件订阅，见下
destroy()卸载（离开页面/弹窗关闭时调用，防内存泄漏）

事件 ​

事件参数说明
ready—首次渲染完成
change—数据变更（含载入），可提示「未保存」
errorerr接口/渲染错误
venuebackendId场馆身份确定或变化（载入/新建/导入/首次保存建档）；本地场馆为 null，宿主路由同步只订这一个事件
dirtyv脏状态直报：编辑 true、保存或载入 false；切换拦截存个布尔值即可

on() 返回退订函数：

js
const off = designer.on('dirty', (v) => console.log('脏状态', v))
// 页面卸载前：off()  或  designer.destroy()

注意事项 ​

  • 同一页面只挂载一个设计器实例（内部 store 为模块级单例）。
  • 挂载容器需给定宽高（设计器充满容器）。
  • 样式已加 .seatmap-designer 前缀隔离，不会污染宿主页面；宿主不要覆盖 .seatmap-designer 内部样式。
  • 事件回调异常会被捕获并 console.error，不会中断设计器。
