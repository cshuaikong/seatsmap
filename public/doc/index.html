座位图系统 · 文档中心 ​

座位图整体解决方案：设计端（画场馆 / 画分区 / 画座位 / 出票预览）产出场馆数据，经后端接口存取，由选座端（uniapp H5 / 微信小程序）呈现给用户购票选座。

┌────────────────────┐    ┌──────────────────┐    ┌─────────────────────────┐
│      设计端 app/    │    │   后端（贵司）     │    │  选座端 picker/         │
│  Vue3 + Leafer 画布 │    │  venue / seat    │    │  uniapp Vue3           │
│  · 绘制分区/排/座位  │───▶│  增删查改、图片    │◀───│  · H5 网页版            │
│  · 类别/标签/水印    │    │  上传、状态同步    │    │  · 微信小程序           │
│  · 全量/增量保存     │    │                  │    │  · 选座/合计/确认        │
└────────────────────┘    └──────────────────┘    └─────────────────────────┘
        │                                            │
        └──── 打包交付：seatmap-designer 组件（JS / Vue / npm pack）────┘

三端定位 ​

端代码目录技术栈交付形态
设计端（SeatMap Designer）app/Vue 3 + Leafer 2.x（canvas 渲染）压缩包交付（seatmap-designer-pkg.tar.gz），解压后安装
选座端 · H5picker/uniapp（Vue3）编译 H5，Vite 5uniapp 插件安装（seatmap-picker），编译 H5 网页
选座端 · 小程序picker/uniapp（Vue3）编译微信小程序uniapp 插件安装（seatmap-picker），编译微信小程序

三端共享同一份核心数据层 packages/core（后端数据格式 ↔ 内部模型转换，纯 JS 零依赖），保证「设计端画的 → 后端存的 → 选座端显示的」三方数据口径完全一致。

核心概念速览 ​

  • 数据进出全显式：设计器不直接发任何网络请求。宿主用 setData(venue, seatlist) 喂数据、用 saveHandler 回收保存、用 uploadHandler 上传图片。
  • 坐标系统：分区 path 是分区内容坐标，世界坐标 = path + 分区偏移；排 x/y 是世界坐标；座位 x/y 是相对排原点、沿排方向的局部坐标。详见后端接口文档。
  • 保存模式：save_type: "full" 全量（首次/兜底）、"delta" 增量（日常保存只带座位增删改，KB 级）。

快速上手（三步） ​

  1. 跑设计端：cd app && npm install && npm run dev（演示页，?venue_id=<id> 拉真场馆）
  2. 跑选座端：cd picker && npm install && npm run dev:h5（H5，端口 5184）
  3. 微信小程序：npm run dev:mp-weixin 编译到 picker/dist/dev/mp-weixin，微信开发者工具导入即可

交付包 ​

cd app && npm run pack 一键产出 seatmap-designer-pkg.tar.gz（含 ES / UMD 双产物），见打包与交付说明。
