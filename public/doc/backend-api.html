后端接口文档 ​

座位图系统后端接口。供设计端与选座端共用——设计端的数据进出、选座端的数据加载与状态刷新，全部走以下接口。

⚠️ 仅用于测试对接：以下接口定义只用于前端与后端联调时验证数据格式契约，本仓库不提供后端实现。实际生产接口需由对接方（后端团队）自行实现——按本文档的接口形态、请求/响应字段与数据契约开发即可，前端已按此契约对接，无需改动。

概述 ​

  • 统一响应包：所有接口返回 { code, msg, data }，code === 0 为成功，data 为业务数据,对接方可根据业务调整，不影响功能。
  • 请求地址：示例后端：https://seatmap.web.jinsc.cn。
  • 鉴权：自行实现。
  • 压缩：保存请求体默认 Content-Encoding: gzip（增量也可能一次几千条）。

接口总览 ​

接口地址方法用途调用方
GET /venue/listGET场馆列表选座端场馆列表页、设计端演示壳
GET /venueGET场馆主体（分区/排/底图/类别，不含座位）两端加载
GET /venue/seatsGET场馆座位列表（section_id 可选，指定时只返回该分区座位，供按需刷新）两端加载 / 选座端分区刷新
POST /venue/savePOST保存场馆（新增+保存一体，全量/增量）设计端
GET /venue/deleteGET删除场馆设计端演示壳
POST /uploadPOSTmultipart 图片上传（底图/水印 logo 共用）设计端

设计端组件本身不发任何请求：加载由宿主调用接口后 setData 喂入、保存由宿主在 saveHandler 中调用 POST /venue/save。下表接口是「演示壳 / 选座端」实际对接的参考形态，你们可按需调整，只要保住数据格式契约即可。

1. 场馆列表 ​

接口地址

GET /venue/list

接口说明

返回全部场馆的概要（id / name / type / baseScale 等，其余字段原样透传）。数据量小（一条一个场馆），可全量返回。

功能 / 目标：给选座端列表页提供「可选场馆」入口清单，用户点选进入选座；同时供设计端演示壳左侧列表选择要编辑的场馆。

请求参数

无。

返回结果

data 为场馆对象数组。

返回示例结构

jsonc
{
  "code": 0,
  "msg": "ok",
  "data": [
    { "id": "venue_ms0mrtow_w4csgyq", "name": "演示体育馆", "type": "WITH_SECTION", "baseScale": "4.74", "version": 0, "created_at": "2026-07-26 01:16:51", "updated_at": "2026-08-02 23:05:37" }
  ]
}

2. 场馆主体 ​

接口地址

GET /venue?venue_id=<id>

接口说明

返回场馆主体：分区轮廓（sections[].path）、排骨架、类别（categories）、底图（image）等，不含座位。

功能 / 目标：分段加载的第一阶段——先拿骨架渲染分区轮廓，用户（或设计师）立刻看到场馆形状，座位后到再并入（渐进加载，首屏更快）；也是设计端编辑加载的入口。

请求参数

参数类型必填说明
venue_idstring是场馆 id

返回结果

data.venue 为场馆主体对象（结构见场馆数据格式）。

3. 场馆座位列表（支持按分区过滤） ​

接口地址

GET /venue/seats?venue_id=<id>
GET /venue/seats?venue_id=<id>&section_id=<id>   # section_id 可选

接口说明

返回场馆的全部座位；传 section_id 时只返回该分区座位。

注意：历史数据中可能存在 row_id 指向已删除排的残留座位（孤儿座位）。设计端载入时跳过渲染并在状态栏提示数量，随下次保存的 seat_delete 自动清理；选座端渲染同样按 row_id 匹配排，匹配不到的座位不会显示。后端可在保存时顺带物理删除，无需单独接口。

功能 / 目标：

  • 不带 section_id：分段加载的第二阶段——座位到达后并入渲染，也是选座端进入场馆后的初始选座数据（万级座位，需支持大响应 gzip）。
  • 带 section_id：并发购票场景的按需刷新——已售/锁定状态在变，前端只轮询当前视口可见的分区，局部更新该分区座位状态；不动视口、不重载全馆，避免万级座位反复全量拉取。选座端配合 getVisibleSectionIds() 只请求看得见的分区，再 updateSectionSeats() 局部重绘。

请求参数

参数类型必填说明
venue_idstring是场馆 id
section_idstring否分区 id；指定时只返回该分区座位（按需刷新）

返回结果

data.seatlist 为座位数组（结构见座位格式）。

返回示例结构

jsonc
{
  "code": 0, "msg": "ok",
  "data": {
    "seatlist": [
      { "id": "0mu5cop9y43f7vt5vkwhoop", "ven_id": "qommsDFY-YTAER0QOMlPd", "sec_id": "section-1783584064142", "row_id": "vdc0x2gs50hfuhkoap8fb4", "cat_id": 1, "label": "18", "x": 306, "y": 0, "status": 1, "type": 1 }
    ]
  }
}

seatlist 数组可含全馆所有座位，此示例为单条完整结构示意。

4. 保存场馆（设计端） ​

接口地址

POST /venue/save

接口说明

新增 + 保存一体（场馆 id 由客户端生成建档，后端直接存）。请求体为保存 payload，save_type 显式区分两种模式（必填，后端不做隐式推断）：

  • "full" 全量：首次保存 / 兜底，携带 venue 主体 + seatlist 全量座位（空数组 = 清空所有座位）。
  • "delta" 增量：日常保存，携带 venue 主体（每次仍全量回写）+ seat_upsert（新增/修改座位）+ seat_delete（删除的 id 清单）。

乐观锁（并发控制）：venue.version 为比对基准，保存必填（缺失返 400）。后端保存前比对 version 与库中当前值：

  • 一致 → 应用写入，version + 1，响应 data.version 带回新版本号（新建场馆建档后为 0）。
  • 不一致 → 不写入任何数据，返回 code: 409（HTTP 仍为 200，业务码在响应体），msg 示例：保存冲突：场馆已被他人修改，请刷新后重试。

功能 / 目标：设计端画完场馆后持久化。全量首次建档；增量是日常保存，只带座位增删改（KB 级），万级场馆也能快速保存。请求体默认 gzip 压缩（增量也可能一次几千条）。乐观锁防止多人/多标签页同时编辑同一场馆时静默互相覆盖。

请求参数（请求体，JSON）

字段类型必填说明
save_typestring是"full" / "delta"，后端不做隐式推断
venueobject是场馆主体，两种模式都全量回写（结构见场馆数据格式）；其中 version 必填，为乐观锁比对基准
seatlistarrayfull 必填全量模式：全量座位（空数组 = 清空）
seat_upsertarraydelta 可选增量模式：新增 + 修改的座位记录
seat_deletearraydelta 可选增量模式：删除的座位 id 清单（可能包含当前 venue 中已不存在的排上的残留座位 id——设计端载入时自动收集这类「孤儿座位」并随保存捎带清理，后端按 id 直接删即可，不存在则忽略）

返回结果

  • 成功：{ code: 0, msg: "保存成功", data: { version: <新版本号> } }——客户端须用 data.version 更新本地基准，否则下次保存必冲突。
  • 失败：{ code: 400, msg: "具体错误" }；版本冲突 { code: 409, msg: "保存冲突：..." }（HTTP 状态恒为 200，错误以响应体 code 为准）。

客户端冲突处理：收到 409 后不要直接重试（增量 diff 基准已与服务端脱节）。唯一出口是重新拉取场馆最新数据（本地未保存改动放弃）——重载后 version 基准与 diff 快照一并刷新，可继续编辑保存。

返回示例结构（全量模式请求体）

jsonc
{
  "save_type": "full",
  "venue": {
    "id": "qommsDFY-YTAER0QOMlPd",
    "name": "测试",
    "type": "WITH_SECTION",
    "baseScale": "1.00",

      { "key": 1, "color": "#4CAF50", "label": "普通区", "accessible": false },

      { "key": 3, "color": "#2196F3", "label": "轮椅区", "accessible": true }
    ],
    "sections": [
      {
        "id": "section-1783584064142",
        "name": "分区 1",
        "fill": "#d1d5db",
        "x": -166,
        "y": 13,
        "path": "M277,245A602.3,602.3 0 0 1 676,245L630,468A452.35,452.35 0 0 1 448,503A366.23,366.23 0 0 1 314,469L277,245Z",
        "type": "path",
        "rows": [
          { "id": "3C8ZSycH", "label": "", "x": 168.24, "y": 290.6, "rotation": 0.51, "seatSpacing": 18, "seats": [] }

返回示例结构（增量模式请求体）

jsonc
{
  "save_type": "delta",
  "venue": { /* 与全量模式相同的完整场馆主体（结构见上方全量示例），此处不重复 */ },
  "seat_upsert": [
    { "id": "0mu5cop9y43f7vt5vkwhoop", "ven_id": "qommsDFY-YTAER0QOMlPd", "sec_id": "section-1783584064142", "row_id": "vdc0x2gs50hfuhkoap8fb4", "cat_id": 1, "label": "18", "x": 306, "y": 0, "status": 1, "type": 1 }
  ],
  "seat_delete": ["0mu5cop9y43f7vt5vkwhoop"]
}

模式处理规则（后端）

模式处理异常
full取 seatlist 全量删插（空数组 = 清空所有座位）缺 seatlist 返 400
delta取 seat_upsert + seat_delete 做增量（可只传其一，空数组 = 无操作）两张清单都缺返 400
缺失/非法值—400

后端必做

  • 乐观锁校验在同一事务内：version 比对 + venue 主体覆盖 + upsert + delete 必须包在一个事务里，比对不过整体回滚返 409，杜绝「超时后不知道传没传完」的半成品状态。
  • upsert：按 id INSERT ... ON DUPLICATE KEY UPDATE（或等价实现）。
  • delete：按 id 清单批量删除（限该场馆范围）。
  • 分区/排删除：随 venue.sections 全量覆盖，后端连带清理其座位（没有独立删除接口）。
  • 不解压 gzip 时：if (($_SERVER['HTTP_CONTENT_ENCODING'] ?? '') === 'gzip') $raw = gzdecode(file_get_contents('php://input')); 再解析。
  • 超时放宽：max_execution_time、nginx fastcgi_read_timeout / proxy_read_timeout ≥ 120s；41k 座全量建议用批量 INSERT（每 500~1000 条一个语句）。

5. 删除场馆 ​

接口地址

GET /venue/delete?venue_id=<id>

接口说明

删除指定场馆及其全部座位。

功能 / 目标：管理 / 演示场景清理不再需要的场馆（选座端不调用）。

请求参数

参数类型必填说明
venue_idstring是场馆 id

返回结果

{ code: 0, msg: "ok" }；失败返回非 0 code。

返回示例结构

jsonc
{ "code": 0, "msg": "ok" }

6. 图片上传（设计端） ​

接口地址

POST /upload

接口说明

multipart 表单上传图片（字段名默认 file），返回图片完整 URL。底图 / 水印 logo 共用同一接口。

功能 / 目标：设计端给场馆加底图 / 水印 logo 的图片通道，画布渲染需要可直接引用的 URL。 契约收紧：返回的 data.url 必须是 http(s):// 开头的完整 URL——设计器收到相对路径会直接报错（不静默兼容）。

请求参数（multipart）

参数类型必填说明
filefile是图片文件（字段名默认 file，可配）

返回结果

成功 { code: 0, msg: "ok", data: { url } }；失败 { code: 400, msg: "错误信息" }。

返回示例结构

jsonc
{
  "code": 0,
  "msg": "ok",
  "data": { "url": "https://seatmap.web.jinsc.cn/uploads/venue-bg-20260813.png" }
}

数据格式 ​

venue 场馆 ​

字段类型说明
idstring场馆 id（客户端生成，保存时后端直接存）
namestring场馆名
typestring如 WITH_SECTION，原样透传
baseScalestring/number场馆级缩放，只用于座位尺寸（座位边长 = 12 ÷ baseScale），与坐标位置无关
categoriesarray座位类别 [{ key, color, label, accessible, price }]；accessible=true 为无障碍区；price 为单价（选座端合计用）
imageobject/null底图 { src, x, y, w, h, baseW, baseH }（src 为完整 URL 或 dataURL）；也容忍 JSON 字符串形式；删除底图后为 null
themestringlight / dark，原样透传
showSeatBarsbool座位条显示开关（false 时画布不渲染座位条）
readonlynumber1 = 只读（设计端加载后禁用所有编辑）
sectionsarray分区列表
其余任意字段—原样透传，保存时回写（type/options/created_at 等）

sections[] 分区 ​

字段类型说明
idstring/number分区 id（客户端生成）
namestring分区名
fillstring填充色，如 #4CAF50
pathstringSVG path 轮廓，分区内容坐标；世界坐标 = path + (x, y)
x / ynumber分区偏移（保存时设计器统一归 0，path 存世界坐标，几何等价）
loosebool可选，true = 散座分区（无名称无轮廓的座位容器，画布不渲染轮廓与标签）
cat_idnumber可选，分区默认类别 key
watermarkany可选，赞助商水印对象（text/logo/opacity/rotation 等），原样存取
labelany可选，分区标签样式（text/visible/fontSize/rotation/dx/dy），原样存取
typestring保存时写 "path"
rowsarray排列表
其余任意字段—原样透传（pathPoints 除外，会被丢弃）

rows[] 排 ​

字段类型说明
idstring/number排 id（客户端生成，座位通过 row_id 关联）
labelstring排号
labelPosstring排标签显示位置：start / end / both / none
x / ynumber排原点，世界坐标（不加分区偏移）
rotationnumber排方向，角度（-180~180）
curvenumber排弧度（总圆心角，度），无则 0
seatSpacing / rowSpacingnumber可选，座位间距 / 排间距
其余任意字段—原样透传

seatlist[] 座位 ​

字段类型说明
idstring/number座位 id（客户端生成）
ven_idstring/number所属场馆 id
sec_idstring/number所属分区 id（可空）
row_idstring/number所属排 id（分组唯一依据，排必须存在于 venue.sections，否则座位被当孤儿跳过）
cat_idnumber类别 key
labelstring座位号
x / ynumber相对排原点、沿排方向的局部坐标（y 通常为 0）
statusnumber1 可选 / 2 已预订 / 3 已保留 / 0 禁用
typenumber1 普通座位（椅子/凳子/长凳等类型扩展）

关键约定 ​

坐标系统 ​

分区 path：分区内容坐标 → 世界坐标 = path + (section.x, section.y)
排   x/y：世界坐标（不加分区偏移）
座位 x/y：相对排原点、沿排方向的局部坐标（后端换算：世界坐标 → 旋转到排方向后取相对量）
baseScale：只用于座位尺寸（边长 = 12 ÷ baseScale），与坐标位置无关

id 全部客户端生成 ​

venue / section / row / seat / image 的 id 均由前端生成（字符串主键），后端不改写内容字段（坐标、label 等原样存取），只维护 updated_at。场馆新建 = 首次保存建档（设计器生成 venue.id 提交），也可经 newVenue({ id, name, ... }) 预分配。

坐标精度 ​

前端保存前统一 toFixed(2) 两位小数，后端不二次处理。

扩展字段 ​

sections[].watermark / sections[].loose / sections[].label / venue.image 整 JSON 原样存取。
